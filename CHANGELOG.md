# Changelog


## 1.0.1_beta

- Added support for QR codes with rounded and stylized finder patterns.
- Improved compatibility with branded QR codes.
- Added fallback finder geometry reconstruction while preserving the normal fast scan path.
- Added regression coverage for rotated, blurred, and low-contrast stylized QR codes.


## v1.0.0 — Initial Release

### Core

- Fully native Android QR scanner written in C.
- NativeActivity-based architecture with no Kotlin or Java application code.
- Camera2 NDK and AImageReader camera pipeline.
- Offline QR decoding using quirc.
- Arbitrary QR byte payload support.
- QR result screen with copy and rescan actions.
- Camera permission handling with direct App Settings fallback.

### Rendering

- Direct RGB565 rendering through ANativeWindow.
- Native grayscale live camera preview.
- Center-crop preview with sensor orientation handling.
- Animated QR scanning overlay.
- Custom lightweight 5x7 bitmap font.
- Resolution-aware UI and text scaling.
- Custom vector launcher icon.

### Performance / Size

- Size-first native build using:
  - `-Oz`
  - LTO
  - function/data sections
  - linker garbage collection
  - stripped native binary
- No AndroidX.
- No Compose.
- No CameraX.
- No Play Services.
- No network permission.
- No analytics or tracking.
- Zero runtime cache or user data generated by TinyQR itself during normal use.

### ABI

- arm64-v8a only

### TinyQR Challenge

Initial public baseline for the TinyQR optimization challenge. See [BENCHMARK.md](BENCHMARK.md) for the v1.0.0 release-size measurements.

Future releases should aim for:

- smaller release APKs
- smaller `libtinyqr.so`
- faster startup
- lower preview CPU cost
- lower memory usage
- equal or faster QR decode latency

without removing existing functionality.
